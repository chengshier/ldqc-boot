# 绿动全城整体整改进度——第三批

> 更新时间：2026-07-27  
> 分支：`refactor/market-ready-phase1`  
> 本文只记录代码与材料状态，不把未执行的数据库、编译、接口、真机验证标记为通过。

## 一、本批已提交代码

### 1. 赛事报名

- 赛事增加报名开始/截止时间、单次人数限制、支付方式和报名须知。
- 报名订单增加订单号、请求号、活动唯一键、赛事快照、金额、支付和取消字段。
- 报名人以后端登录态为准，价格、支付状态、赛事状态和名额全部由服务端计算。
- 免费赛事直接确认报名；付费赛事在微信支付未接入时明确阻断，不创建虚假已支付订单。
- 通过条件更新原子占用赛事名额，取消和支付超时后释放名额。
- 历史报名统一标记 `LEGACY_REVIEW`，避免沿用旧前端可写 `payStatus` 的不可信状态。
- 小程序活动列表、详情、报名页和报名订单页已移除 Mock 与客户端支付状态。

### 2. 关注与达人

- 关注关系增加有效唯一键，清理自关注和重复关系，重新校准关注数与粉丝数。
- 关注发起人固定取当前登录用户，旧接口也忽略客户端 `uid`。
- 关注、取消关注、状态、关注/粉丝列表和关注动态统一进入业务服务。
- 达人列表只展示达人认证通过且启用的账号。
- 达人主页拆分为公开摘要、社区作品、专业教程和正式课程分页。
- 作品、教程和课程均只返回已发布内容。
- 达人资料编辑仅允许当前认证达人修改简介、标签、封面、描述和在线状态。
- 小程序达人列表、主页和粉丝/关注列表已移除 Mock，并统一关注按钮状态。

### 3. 场馆入驻与运营工作台

- 场馆增加运营用户、来源申请、经营主体和服务说明字段。
- 新增场馆入驻申请表及完整工作流：提交、列表、详情、取消、审核通过、审核驳回。
- 审核通过后自动创建场馆，并将申请用户绑定为场馆运营者。
- 场馆运营者只能维护自己场馆的封面、图集、营业时间、电话、标签、介绍和服务说明。
- 公开场馆列表支持服务端关键词、类型和坐标范围筛选，不再只筛当前分页结果。
- 小程序新增入驻申请、申请记录和场馆工作台。
- 管理端新增场馆入驻审核工作台，可预览营业执照和场馆图片。

### 4. 优惠券领取规则

- 券模板增加认证要求和领取开始/结束时间。
- 领取资格改为服务端读取成长等级和认证状态，不再相信客户端参数。
- 正式领取使用模板行锁，在同一事务内校验限领、库存、绿豆和有效期。
- `requestId` 必填并增加用户级唯一索引，重复请求幂等处理。
- 旧 `extJson.receive_auth_required` 会迁移到显式字段。
- 公开券列表只返回当前可领取、有库存且已启用的模板。
- 小程序领券 API 不再上传成长等级和认证状态。
- 管理端模板表单补充认证要求和领取时间窗口。

### 5. 推荐反馈

- 新增推荐反馈表，支持曝光、点击、停留、视频完成和不感兴趣事件。
- 用户身份以后端登录态为准，客户端不能指定其他用户。
- 不感兴趣内容会从后续推荐中排除。
- 点击、停留和视频完成会形成行为分，参与推荐排序。
- 小程序推荐页接入曝光、点击和长按“不感兴趣”上报。

### 6. 生产 Mock 与接口契约

- 资讯和露营首页移除接口为空/异常时的假新闻和假营地回退，改为真实空态与重试提示。
- 个人中心增加赛事报名、我的兑换、体育课程、绿动有约、场馆入驻、场馆工作台、关注和粉丝入口。
- 修复消息已读和兴趣提醒接口 JSON Body 与 `@RequestParam` 不一致问题。
