# 场馆预约与经营结算延期边界

更新日期：2026-07-28

## 一、本轮已经完成的场馆范围

本轮场馆能力以“专业资料入驻与运营维护”为边界：

1. 用户提交场馆入驻申请；
2. 平台运营人员审核营业资质、地址、坐标和场馆图片；
3. 审核通过后自动创建场馆并绑定申请用户为场馆运营者；
4. 场馆运营者维护自己场馆的公开资料；
5. 小程序按关键词、场馆类型和位置范围查询场馆；
6. 优惠券核销员可按配置范围在场馆核销优惠券。

以上能力不等同于场馆预约交易。

## 二、本轮明确不实现的内容

以下能力延期到独立阶段，不在当前 PR 中创建占位订单或假支付流程：

- 场地、球馆、泳道、教室等可预约资源模型；
- 日期、时间段、可售数量和临时闭馆；
- 工作日、周末、节假日及会员价规则；
- 下单锁场、支付超时释放和防超卖；
- 微信支付、支付回调和交易对账；
- 用户取消、商家取消、退款和违约规则；
- 到店核销、使用完成和爽约处理；
- 平台抽佣、场馆结算和财务对账；
- 预约经营数据和收入看板。

## 三、延期原因

当前规划尚未确认以下业务规则，直接开发会产生不可控返工：

1. 预约单位是“整个场地”还是“单个人次”；
2. 一个场馆是否包含多个场地和不同项目；
3. 时段由平台生成还是场馆自行维护；
4. 是否允许跨时段、连续时段和团体包场；
5. 用户取消时限和退款比例；
6. 场馆拒单、临时闭馆及已支付订单处理；
7. 平台服务费和场馆结算周期；
8. 优惠券、绿豆和现金是否可组合支付。

## 四、进入预约阶段的准入条件

开始开发前必须先确认并形成文档：

- 场馆、场地、项目和时段的数据关系；
- 价格规则优先级；
- 订单状态机；
- 支付与退款状态机；
- 库存锁定和释放规则；
- 到店核销规则；
- 平台与场馆结算规则；
- 用户端和场馆端页面清单；
- 管理端异常订单和退款工作台；
- 测试账号、支付环境和验收场景。

## 五、当前产品展示要求

在预约阶段正式完成前：

- 场馆详情只能展示公开资料、联系方式、开放时间及可用优惠券；
- 不展示“立即预约”“支付订场”等会误导用户的按钮；
- 不创建只有页面或只有订单表的占位预约流程；
- 运营材料中统一表述为“场馆入驻与资料展示已完成，在线预约延期”。
