## 三、动态审核结果规则

| 微信或系统结果 | 平台动作 |
|---|---|
| 文案和全部媒体均 `pass` | 自动发布并进入推荐、关注和达人主页 |
| 任一任务 `risky` | 自动驳回整条动态并通知用户 |
| 任一任务 `review` | 保持待审核，进入运营人工复核 |
| 微信接口异常 | 状态 3，按退避策略自动重试 |
| 媒体回调约 35 分钟未到达 | 重新提交媒体审核 |
| 连续 5 次失败 | 状态 4，进入人工待办 |
| 视频封面未生成或生成失败 | 不自动发布，等待处理 |
| 修改后重新提交 | 废弃旧动态审核任务，审核最新快照 |

## 四、SQL 执行前置条件

1. 使用 MySQL 5.7 测试库完整备份后执行。
2. 按 `docs/market-ready` 与 `doc/sql` 中的执行顺序逐份执行。
3. 结构迁移、菜单权限、历史数据修复和 UAT 数据必须分开执行。
4. 执行 `doc/sql/content_audit_retry_upgrade.sql`，检查状态 3/4、重试字段和历史任务初始化。
5. 执行 `doc/sql/dynamic_content_auto_audit_upgrade.sql`，检查业务聚合与 `trace_id` 回调索引。
6. 媒体回调 Token、AppID 和 AppSecret 通过环境变量配置，不写入 SQL。
7. 每份 SQL 执行后检查字段、唯一索引、历史状态和可重复执行性。
8. 未在测试库执行成功前，不得进入生产库。
