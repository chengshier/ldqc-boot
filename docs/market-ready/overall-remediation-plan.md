# 绿动全城整体整改与产品化优化——后端执行基线

## 1. 分支与合并策略

- 正式基线：`master`
- 唯一整改分支：`refactor/market-ready-phase1`
- 本轮所有后端、SQL、接口、权限与测试记录均持续提交到该分支。
- 通过一个持续更新的 Draft PR 合并回 `master`，不再按阶段创建额外分支。
- 每批提交必须保持可编译、可回滚，并在 PR 描述或提交记录中注明影响模块、SQL、接口和测试状态。

## 2. 产品边界

- 底部菜单和首页现有 Tab 本轮不调整。
- 优惠券与商城保持独立业务。
- 相册社交停止建设；好友关系只保留关注与粉丝；私聊和群聊不作为本轮核心。
- 底部“发布”只承担普通社区图文与短视频 UGC。
- 官方资讯、赛事、赛事回顾、初期场馆与培训内容由管理端维护。
- 达人正式课程、章节、课时和长视频后续由个人中心达人工作台维护。
- 场馆后续通过入驻申请、平台审核和场馆工作台维护专业资料。

## 3. 后端最高优先级

### P0

1. 生产配置、正式资源地址和 Mock 隔离。
2. 统一媒体地址、图片封面、视频元数据和处理状态。
3. 内容发布者身份服务端确定，建立草稿、处理中、待审核、已发布、拒绝、下架状态。
4. 短视频压缩/转码任务、封面生成、失败重试。
5. 长视频课程、章节、课时、播放权限、试看、进度和断点续播。
6. 优惠券领取资格、库存幂等、动态码、核销权限、使用范围和原子核销。
7. 赛事重复报名、名额、截止时间、免费/付费边界、订单和个人信息保护。
8. 绿动有约申请、审核、原子人数、审核后信息可见规则和通知。
9. 商城库存、绿豆、兑换订单、商品快照和履约状态事务一致性。
10. Query/Body、分页、状态枚举、金额和时间格式统一。

### P1

- 达人主页聚合接口与统计校准。
- 关注动态流与全局关注状态。
- 场馆、培训、户外和优惠券关联。
- 消息中心和审核通知。
- 管理端所需的运营聚合接口、详情接口和批量处理接口。

## 4. 管理端接口设计原则

管理端不得直接暴露大量难理解的底层配置字段。后端接口按运营业务设计：

- 列表：关键搜索条件、状态、负责人、更新时间和待处理数量。
- 详情：业务信息、用户信息、媒体预览、规则说明、处理记录。
- 动作：审核通过、驳回、补充资料、上下架、发货、核销异常处理等明确动作。
- 结果：操作结果、失败原因、影响数据和审计日志。
- 配置：仅保留运营真正需要的配置；代码枚举、技术字段和内部 ID 使用选择器及中文标签封装。

## 5. 分批执行顺序

1. 工程配置、接口契约与媒体基础。
2. 社区发布、分类、标签、审核、达人和关注。
3. 培训及长视频课程。
4. 赛事与绿动有约。
5. 场馆、户外、优惠券及核销。
6. 商城兑换、履约与个人记录。
7. 历史功能清理、性能、权限和全量回归。

## 6. 每批交付要求

每项功能必须同时核对并交付：

- SQL 与升级说明；
- Entity/Model、Mapper/DAO、Service、Controller；
- 权限码、菜单和审计；
- 小程序接口；
- 管理端接口；
- 状态机与错误码；
- 测试数据和测试用例；
- 已验证、未验证和环境限制说明。

禁止仅有表、仅有接口、仅有页面或仅能编译就标记完成。
