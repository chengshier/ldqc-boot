# 社区动态微信自动审核接入说明

更新日期：2026-07-28

## 一、目标

社区动态不再要求运营人员逐条实时审核。系统优先使用微信小程序官方内容安全能力：

- 动态文案：`msg_sec_check`；
- 动态图片：`media_check_async`；
- 社区短视频：审核文案、视频封面和后端 FFmpeg 抽取的封面；
- 不接入腾讯云、阿里云或其他收费内容安全服务；
- 不对视频本体做收费的逐帧审核。

管理员后台继续保留，主要处理微信建议复核、接口异常、回调超时、媒体不可访问、用户举报和运营下架。

## 二、发布状态流转

```text
用户提交动态
  → 保存为待审核
  → 微信文本审核
  → 图片或视频封面异步审核
      ├─ 全部 pass：自动发布
      ├─ 任一 risky：自动驳回
      ├─ 任一 review：保持待审核，进入人工待办
      └─ 接口异常/回调超时：自动重试，耗尽后进入人工待办
```

修改后重新提交会废弃上一轮动态审核任务，按最新文案和媒体重新生成任务，避免旧结果影响新内容。

## 三、微信请求场景

微信内容安全接口的 `scene` 按内容实际用途传递：

| 内容 | scene | 说明 |
|---|---:|---|
| 社区评论、新闻评论 | 2 | 评论场景 |
| 社区动态文案、图片和视频封面 | 3 | 论坛/UGC 场景 |

首次审核与自动重试必须使用相同场景，避免同一内容在重试后切换审核策略。

## 四、微信后台配置

### 1. 后端配置

在测试和生产环境配置中增加：

```yaml
WECHAT:
  app-id: ${WECHAT_APP_ID}
  app-secret: ${WECHAT_APP_SECRET}
  message-token: ${WECHAT_MESSAGE_TOKEN}
```

要求：

- `message-token` 使用单独的随机字符串，不要与 app-secret 相同；
- app-secret 与 message-token 只放在环境变量或密钥管理中；
- 不得写入 Git、前端、小程序或数据库初始化脚本。

### 2. 消息推送地址

微信后台配置的媒体审核回调地址应指向：

```text
https://你的正式接口域名/blade-contentaudit/wechat/media-callback
```

若外部 API 统一带 `/api` 代理前缀，则按实际 Nginx 路由填写，例如：

```text
https://你的正式域名/api/blade-contentaudit/wechat/media-callback
```

配置要求：

- Token 与 `WECHAT.message-token` 完全一致；
- 第一阶段使用明文消息模式；
- 推荐选择 JSON 数据格式，后端同时兼容基础 XML 字段；
- 回调地址必须允许微信服务器公网访问；
- GET 验证和 POST 回调均不要求用户 Token，但必须通过微信签名校验。

### 3. 回调格式兼容

后端同时兼容：

- 新版回调：`result.suggest = pass / risky / review`；
- 旧版回调：`isrisky = 0 / 1`；
- 下载或处理异常：`status_code != 0`。

旧版 `isrisky=0` 映射为通过，`isrisky=1` 映射为拒绝；`status_code` 非零时不直接判定内容违规，而是进入自动重试，耗尽后再转人工处理。

## 五、媒体地址要求

提交给微信的动态图片和视频封面必须满足：

- HTTP 或 HTTPS 公网地址；
- 微信服务器可以直接访问；
- 不能依赖浏览器 Cookie、用户 Token 或内网地址；
- 有效期应覆盖异步审核和重试时间；
- MinIO/OSS 私有桶应生成足够长的签名 URL，或使用受控的公开审核地址。

无法被微信访问的媒体不会自动通过，会进入自动重试或人工审核。

## 六、审核任务

| 业务类型 | 含义 | 审核方式 |
|---|---|---|
| `IMG_DETAIL_TEXT` | 动态文案 | 微信同步文本审核，scene=3 |
| `IMG_DETAIL_MEDIA` | 动态图片或视频封面 | 微信异步媒体审核，scene=3 |
| `TREND_COMMENT` | 社区评论 | 微信同步文本审核，scene=2 |
| `NEWS_COMMENT` | 新闻评论 | 微信同步文本审核，scene=2 |

状态：

| 状态 | 含义 |
|---|---|
| 0 | 调用中或等待媒体回调 |
| 1 | 审核通过 |
| 2 | 审核拒绝 |
| 3 | 等待自动重试 |
| 4 | 等待人工处理 |

媒体回调约 35 分钟未到达时，任务进入重试；最多尝试 5 次，之后转人工待办。

## 七、管理端处理

菜单“自动审核异常”支持：

- 按动态文案、动态媒体、社区评论和新闻评论筛选；
- 查看失败原因和尝试次数；
- 预览动态图片或视频封面；
- 立即重新调用微信审核；
- 人工通过；
- 人工拒绝并填写原因。

人工通过某一张图片不代表整条动态立即发布。系统会重新汇总同一动态的文案与全部媒体任务，只有全部通过才公开。

## 八、测试用例

至少验证：

1. 正常文案＋一张正常图片自动发布；
2. 正常文案＋多图，全部回调通过后发布；
3. 文案明确违规自动驳回；
4. 任一图片明确违规，整条动态驳回；
5. 微信返回 `review`，动态进入人工待办；
6. 微信接口超时，任务自动重试；
7. 媒体回调重复发送，不重复发布或重复奖励；
8. 用户修改后重提，旧审核任务不影响新内容；
9. 视频封面生成完成后才提交媒体审核；
10. 视频封面生成失败，动态不自动发布；
11. 管理员在自动审核完成前人工通过，后续回调不能反向覆盖已发布状态；
12. 管理员人工拒绝后，后续旧回调不能重新发布内容；
13. 新版 `result.suggest` 回调正确处理；
14. 旧版 `isrisky` 回调正确处理；
15. `status_code` 下载异常进入重试而不是误判违规；
16. 动态初次审核与自动重试均保持 scene=3，评论保持 scene=2。

## 九、当前边界

本阶段没有接入：

- 收费的腾讯云、阿里云内容安全；
- 视频本体逐帧审核；
- 音频内容审核；
- OCR 后二次文本审核；
- 用户举报自动判罚。

这些能力应根据真实内容规模、违规率和运营成本单独评估，不应在没有业务数据时提前增加费用与系统复杂度。
